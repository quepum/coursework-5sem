\section*{Аннотация}

Проект PySATL предоставляет инструменты для статистического анализа данных.
Библиотека \texttt{pysatl-criterion} содержит несколько сотен критериев для
различных семейств распределений, а \texttt{pysatl-experiment} предоставляет фреймворк
Monte-Carlo экспериментов: сегодня в нём доступны типы \texttt{critical\_value},
\texttt{power}, \texttt{time\_complexity} и \texttt{generation\_only}. Эти эксперименты
позволяют оценить мощность критерия при конечном объёме выборки, но не дают
асимптотического сравнения критериев.

В качестве меры асимптотического сравнения в работе используется эффективность по
Ходжесу--Леману. Критерии сравниваются по скорости, с какой их мощность
$\pi_n(\theta)$ при фиксированной альтернативе $\theta$ и фиксированном уровне значимости
$\alpha$ стремится к единице. Ошибка второго рода при этом убывает экспоненциально,
\[
    1 - \pi_n(\theta) \;\approx\; C\,\exp\bigl(-n\,\rho(\theta)\bigr),
\]
где $\rho(\theta)$~--- \emph{показатель скорости} критерия. Отношение показателей двух
критериев определяет их асимптотическую относительную эффективность:
\[
    \mathrm{ARE} = \frac{\rho_1(\theta)}{\rho_2(\theta)}.
\]

Цель работы~--- разработать численный метод оценки эффективности по Ходжесу--Леману и
интегрировать его во фреймворк в виде нового типа эксперимента
\texttt{hodges\_\allowbreak{}lehmann\_\allowbreak{}efficiency}. Показатель скорости оценивается по наклону прямой
$\ln\bigl(1 - \pi_n(\theta)\bigr)$ от объёма выборки $n$: мощность $\pi_n(\theta)$
оценивается по выборкам, сгенерированным из альтернативы, а порог отвержения берётся из
предельного распределения статистики, сохраняемого фреймворком. Эксперимент проходит
стандартный конвейер «конфигурация~--- вычисление~--- отчёт».

Основная трудность численного метода связана с тем, что ошибка второго рода убывает
экспоненциально, то есть является редким событием, и не оценивается методом Монте-Карло
при больших $n$. Поэтому этап вычисления сделан подменяемым: численный метод и
аналитический метод (замкнутые выражения для показателя скорости) реализованы как
взаимозаменяемые стратегии, выбор которых задаётся в конфигурации эксперимента.

В границы работы не входят вывод больших уклонений для новых статистик и реализация новых
критериев; аналитические значения эффективности предоставляются коллегой по команде и
используются как эталон при валидации численного метода.

Реализация ведётся на Python $\geq$ 3.10 с использованием NumPy, SciPy, SQLAlchemy; данные
хранятся в SQLite или PostgreSQL, вычисления распараллеливаются. Погрешность оценок
количественно оценивается доверительными интервалами, корректность подтверждается
сопоставлением с аналитическими значениями.

Ожидаемые результаты: новый тип эксперимента, доведённый до состояния, когда он запускается
из CLI и даёт воспроизводимый результат; модуль оценки показателя скорости и эффективности с
доверительными интервалами и двумя стратегиями вычисления; матрица эффективностей для набора
критериев выбранного семейства по 3--5 альтернативам; пример конфигурации, документация и
модульные тесты, проходящие в CI.
